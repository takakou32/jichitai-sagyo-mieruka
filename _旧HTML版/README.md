# 作業見える化

移行作業の内容を見える化する資料。構造の考え方は `設計メモ_情報構造.md` を参照。

- 来年度からの作業者への展開資料（新人向けの画面）
- 作業自動化ツールの設計書の元ネタ（設計者向けの画面）

## 見方

`index.html` をブラウザ（Edge など）で開く。サーバー不要・外部通信なし。

| 画面 | 中身 |
|---|---|
| 新人向け：全体像 | 担当業務・業務領域・役割・年間の流れ |
| 新人向け：環境・システム構成 | 作業者クライアント・DB・確認者端末などのつながり |
| 新人向け：イベント | 作業を発生させる出来事と、そこで発生する作業の流れ |
| 新人向け：作業 | 業務領域ごとの作業（型）と、作業ごとのステップ（スイムレーン図） |
| 新人向け：用語集 | 現場用語 |
| 設計者向け：判断ポイント | 「判断」ステップの一覧（責任範囲で絞り込み可） |
| 設計者向け：決定依頼事項 | 判断者・判断基準が「未定義」の判断。委託元への依頼に使う |
| 設計者向け：自動化候補 | 定型ステップの数 × 使われるイベント数で並べた作業 |

## 編集のしかた

中身はすべて `data/` 配下に書く。表示側（`assets/`）は触らなくてよい。書き方は各ファイルの先頭コメントを参照。

| ファイル | 中身 |
|---|---|
| `data/master.js` | 役割・判断の責任範囲・用語集 |
| `data/overview.js` | 全体像（担当業務・年間の流れ） |
| `data/environment.js` | 環境・システム構成図 |
| `data/domains.js` | 業務領域 → 作業（型） → ステップ |
| `data/events.js` | イベント → 発生する作業の並び |

- ステップの種別は「定型／判断／調整」。
- 判断ステップには `judge`（責任範囲・判断者・根拠）を書く。判断者が決まっていなければ `"未定義"` とすると、決定依頼事項に自動で載る。
- 推測で書いた項目には `status: "要確認"` を付ける。画面上で印が付く。

## 注意

客先固有の情報（団体名・ホスト名・IP・アカウント・件数・住民データ）は書かない。
