# 仕様：手順書の MD 化と、MD ⇔ Excel の変換ツール（v0.1）

> この文書は、現場の MS Copilot（Copilot Chat）に添付して渡すためのもの。
> Copilot は、この文書と、添付された手順書（Excel）をもとに、段階ごとに作業する。
> 〔要確認〕は、段階1の調査で埋める箇所。

---

## 1. 目的

- 手順書の中身を **Markdown（MD）で管理**し、AI に直させやすく、git で差分を読めるようにする。
- 当日に使う手順書（Excel）は、**MD から自動で作る**。見た目・印刷は、今の Excel の手順書と同じにする。
- 今の Excel の手順書を MD に移すため、**Excel から MD に戻す変換**も用意する。

## 2. 前提（現場の環境）

| 項目 | 内容 |
|---|---|
| OS | Windows |
| 使えるもの | PowerShell 5.1、Excel（デスクトップ版）、Java 17、git |
| 使えないもの | Python。外部のモジュールやライブラリの追加（インストールは前提にしない） |
| 文字コード | ファイルは UTF-8（BOM 付き）。PowerShell 5.1 で読み書きするときは `-Encoding UTF8` を必ず付ける |

- ツールは **PowerShell 5.1 から Excel を操作する（COM）** 形で作る。
- 手順書には個人情報は含まれない前提。パスワードなどの秘密情報が書かれていれば、Copilot に渡す前に伏せる。

## 3. 全体の流れ

```
          ┌──────────── 最初の1回・もしものとき ────────────┐
          │                                                  ▼
 今の手順書（Excel） ──[xlsx2md]──▶ 手順書（MD）＝元 ──[md2xlsx]──▶ 当日の手順書（Excel）
                                       ▲    │
                          AI・人が直す ─┘    └─ git で管理（1つの課題＝1つのコミット）
```

- **元は MD だけ**。Excel は毎回 MD から作り直し、直接は直さない。
- 当日に Excel を直してしまったときだけ、`xlsx2md` で MD に取り込み直してコミットする。

## 4. 進め方（段階ごとに、人の合意を取ってから次へ進む）

| 段階 | Copilot がやること | 人がやること |
|---|---|---|
| 1 調査 | 添付の手順書（Excel）を読み、下の「調査で報告すること」を報告する | 報告が実物と合っているか確かめる |
| 2 MD の書き方の決定 | 調査の結果から、5章の書き方を具体化した案を出す。手順書の一部を、その書き方で MD にした見本を付ける | 見本を見て、書き方を決める |
| 3 Excel → MD | `xlsx2md.ps1` を作る | 手順書を1つ変換して、MD を読んで確かめる |
| 4 MD → Excel | ひな形の Excel と、`md2xlsx.ps1` を作る | 作った Excel を、元の Excel と並べて見比べる。印刷して見比べる |
| 5 往復の確かめ | `roundtrip.ps1` を作る | すべての手順書で、往復して同じ MD に戻ることを確かめる |

- 作ったものは、git のコミット（またはバッチ）の形で返す。
- 1つの段階が終わるまで、次の段階に進まない。

### 調査で報告すること（段階1）

| # | 報告すること |
|---|---|
| 1 | ファイルとシートの構成（1つのファイルに何枚のシートがあり、それぞれ何のシートか） |
| 2 | 手順の表の列（列ごとの見出しと、何が書かれているか。例：No、作業、コマンド、確認、チェック欄、備考） |
| 3 | 表の始まる行、見出しの行、繰り返しの単位（1つの手順が1行か、複数行か） |
| 4 | セルの結合の使われ方（どこで、何のために結合しているか） |
| 5 | 画像・図形（画面の写しなど）の数と、どのセルの近くに貼られているか |
| 6 | 書式で意味を持たせているところ（色付きのセル、太字、取り消し線など。何を表しているか） |
| 7 | チェック欄・記入欄（当日に手で書き込む欄）の有無 |
| 8 | 印刷の設定（用紙、向き、印刷範囲、ヘッダー・フッター、改ページ） |
| 9 | 数式・入力規則・リンクの有無 |
| 10 | MD で表しにくいもの（上のどれにも当てはまらないもの） |

## 5. MD の書き方（たたき台。段階2で具体化する）

- 1つの手順書＝1つの MD ファイル。
- 書式（色・罫線・列の幅・印刷の設定）は **MD に書かない**。ひな形の Excel に持たせる。
- 1つの手順を、表の1行ではなく、**見出し＋項目**の形で書く（AI が直しやすく、git の差分が読みやすいため）。

```markdown
---
title: 〇〇業務 移行手順書
version: 1.3
---

# 1. 事前準備

## 1-1 作業フォルダを作る

- 作業: 作業フォルダを作成する。
- コマンド:
  ```
  mkdir D:\work\migration
  ```
- 確認: フォルダができていること。
- 備考:

![作業フォルダ](images/1-1.png)
```

- `#` は章（シートや大きな区切り）、`##` は1つの手順。
- 「作業」「コマンド」「確認」「備考」などの項目名は、調査で分かった列の見出しに合わせる。
- 画像は `images/` フォルダに置き、MD からリンクする。ファイル名は手順の番号にする。
- チェック欄など当日に手で書き込む欄は、MD には書かない。ひな形の Excel に空欄として持たせる。

## 6. 変換ツールの仕様

### 共通

- PowerShell 5.1 のスクリプト。Excel の COM を使う。
- **対応の決まり（どのシートの何列目に何を書くか、表の開始行など）は、設定ファイル1つにまとめる**（`mapping.psd1`）。スクリプトの中に直接書かない。
- Excel は、処理が終わったら必ず閉じる（`Quit()` と `ReleaseComObject`）。途中で失敗したときも閉じる。
- 想定していない作りに出会ったら、推測で処理せず、どこで何が想定外かを表示して止まる。
- 実行結果（成功・失敗）は、終了コードでも返す（0＝成功）。

### `xlsx2md.ps1`（Excel → MD）

```
.\xlsx2md.ps1 -In 手順書.xlsx -Out 手順書.md
```

- 設定ファイルに従ってセルを読み、5章の書き方で MD を書き出す。
- 画像は `images/` に書き出し、MD からリンクする。
- 書式（色など）で意味を持たせている箇所は、段階2で決めた書き方で MD に残す。

### `md2xlsx.ps1`（MD → Excel）

```
.\md2xlsx.ps1 -In 手順書.md -Template ひな形.xlsx -Out 手順書.xlsx
```

- ひな形の Excel を写して、MD の中身を流し込む。ひな形そのものは書き換えない。
- 手順の数に合わせて行を増やし、ひな形の書式（罫線・列の幅・行の高さ）を引き継ぐ。
- 画像は、その手順の行の近くに貼る。
- 印刷範囲と改ページを、中身に合わせて設定する。

### `roundtrip.ps1`（往復の確かめ）

```
.\roundtrip.ps1 -In 手順書.md -Template ひな形.xlsx
```

- MD → Excel → MD と往復させ、元の MD と比べる。
- 違いがなければ「一致」と表示して終了コード 0。違いがあれば、違う行を表示して終了コード 1。

## 7. 運用の決まり

- 元は MD。Excel は `md2xlsx` で作り直すもので、直接は直さない。
- 手順書の直しは、**1つの課題＝1つのコミット**。コミットのメッセージの先頭に、課題管理表の課題番号を書く。
- 当日に Excel を直したときは、`xlsx2md` で MD に取り込み、課題番号を付けてコミットする。
- 直したら `roundtrip` を通してから、Excel を作り直す。

## 8. 完了の条件

- すべての手順書が MD になり、`roundtrip` で一致する。
- `md2xlsx` で作った Excel を印刷して、元の手順書と並べたとき、当日の作業に使える（人が見比べて判断する）。
- 使い方と直し方を書いた `README.md` がある（実行のしかた、設定ファイルの直し方、よくある失敗）。

## 9. 決まっていないこと

- MD の書き方の細部（段階2で決める） 〔要確認〕
- ひな形の Excel を、手順書ごとに持つか、共通の1つにするか 〔要確認〕
- 手順書の置き場所（git のリポジトリ） 〔要確認〕
